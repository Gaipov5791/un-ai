# ТЗ-01. Рабочий процесс и состав команды

**Проект:** голосовой ИИ-ресепшен для рынка Кыргызстана  
**Главная фишка:** естественный голосовой ассистент на кыргызском (с русским и код-свитчем ky/ru)  
**Статус:** утверждено руководителем 5 сентября 2026  
**Дата:** 5 сентября 2026  
**Роли:** руководитель проекта — заказчик этого ТЗ; проект-менеджер — Cursor-агент этой ветки

Документ обязателен для всей разработки. Отклонение только по письменному решению руководителя в чате.

---

## 1. Цель процесса

Собрать **новый продукт**, а не доработку `smart-crm`.

- `smart-crm` не трогаем и не смешиваем с этим репозиторием.
- Не копируем fonio.ai. Берём рыночную архитектуру (телефония → STT → LLM → TTS → действия), своё — сценарии КР и кыргызский голос.
- Велосипед не пишем: SIP, STT/TTS, LLM берём готовыми. Свой слой — оркестрация звонка, кабинет, кыргызский голос, локальные сценарии.

Первый продуктный клин (пока нет отдельного продуктового ТЗ):  
**входящий звонок → запись / перевод на человека / саммари**. WhatsApp — второй канал, не первый.

## 2. Роли

| Роль | Кто | Решение |
|---|---|---|
| Руководитель проекта | Пользователь | Цель, бюджет смысла, утверждение ТЗ, приёмка вех, смена приоритета |
| Проект-менеджер | Этот чат (родительский агент) | План, состав работ, допуск агентов, контроль ТЗ, отчёт, эскалация |
| Исполнители | Подключаемые агенты | Только задача из ТЗ, без смены scope |

Руководитель не обязан читать логи агентов. Ему — короткий статус: сделано / блокер / что утвердить.

ПМ не меняет scope сам. Если задача выходит за ТЗ — стоп и вопрос руководителю.

---

## 3. Сколько агентов подключаем

**В штате — 4 роли. Одновременно в работе — не больше 2 исполнителей + ПМ.**

Больше агентов = конфликт правок, потеря ТЗ, разный стиль. Меньше — узкое место на голосе и кабинете.

### Постоянный состав

| # | Роль агента | Тип в Cursor | Когда включать | Что делает | Чего не делает |
|---|---|---|---|---|---|
| 0 | ПМ | этот чат | всегда | ТЗ, план, приёмка кусков, отчёт | не распараллеливает «на всякий случай» |
| 1 | Исследователь | `explore` | старт вехи, поиск в коде, сравнение стека | факты, файлы, риски | не пишет прод-код |
| 2 | Инженер платформы | `generalPurpose` | голос, API, телефония, оркестрация | ядро звонка и бэкенд | не переписывает кабинет без задачи |
| 3 | Инженер кабинета | `generalPurpose` | лендинг, кабинет, записи | UI и клиентский поток | не меняет голосовой пайплайн без задачи |
| 4 | Ревьюер | `bugbot` или `security-review` | только после вехи или по слову руководителя | дефекты, риски | не «улучшает архитектуру» сам |

Агенты 2 и 3 не работают в одних и тех же файлах в один момент.

### Режим по умолчанию

- Обычный день: **ПМ + 1 исполнитель**.
- Параллель: **платформа и кабинет**, если задачи не пересекаются.
- Ревьюер — после закрытия вехи, не в середине фичи.
- `best-of-n` и толпа агентов «кто лучше придумает» — **запрещены**, пока руководитель не утвердит отдельно.

## 4. Последовательность работы

Каждая фича и каждая веха идут по одному конвейеру. Без шага нельзя перескакивать на следующий.

```
1. ТЗ / критерий приёмки
2. План ПМ (файлы, риск, агент)
3. Исследование (если неясно)
4. Реализация одним исполнителем
5. Проверка по критерию приёмки
6. Короткий отчёт руководителю
7. Следующий кусок только после приёмки или явного «дальше»
```

### Правила шагов

1. **Сначала критерий.** Нет измеримого «готово» — нет работы.
2. **Один кусок — один ответственный агент.**
3. **Сначала заставить звонок говорить, потом красивый кабинет.**
4. **Кыргызский голос — приоритет качества выше, чем число каналов.**
5. **Не начинаем WhatsApp, email, CRM, партнёрку, пока нет стабильного входящего звонка ky/ru.**
6. **Не коммитим и не пушим**, пока руководитель не попросит.
7. **Секреты, ключи API, записи реальных звонков в git не кладём.**

## 6. Формат задачи агенту

ПМ отдаёт исполнителю карточку. Без карточки агент не стартует.

- Цель (1–2 предложения)
- Ссылка на пункт ТЗ
- Файлы / зона
- Критерий «готово»
- Что нельзя трогать
- Что принести в отчёте

Исполнитель в конце возвращает: что сделано, что проверено, что осталось, блокер.

---

## 7. Критерий качества (общий)

Кусок принят, только если:

- закрывает пункт ТЗ, а не «стало лучше»;
- не ломает уже принятое;
- есть способ проверить (скрипт, звонок, экран, тест);
- кыргызский текст и озвучка не заменены молча на один русский;
- нет секретов в репозитории.

---

## 8. Эскалация

ПМ сразу пишет руководителю, если:

- задача требует смены ТЗ;
- нужен платный аккаунт (телефония, голос, WhatsApp);
- два агента претендуют на одни файлы;
- оценка вехи выросла больше чем в 1.5 раза;
- качество кыргызского голоса ниже приемки.
